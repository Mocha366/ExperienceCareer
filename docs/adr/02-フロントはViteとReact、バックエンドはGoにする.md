# フロントは Vite + React + TypeScript、バックエンドは Go にする

## 決定

フロントは Vite + React + TypeScript の SPA にする。Next.js は使わない。

バックエンドは Go にする。

最初の公開ページはフロントだけで出す。データはダミーでよい。Go はまだつながない。閲覧者ログインも SSR も、この段階では不要。

ホスティング、データベース、認証基盤は未決のままにする。

## 切った案

- Next.js
- 最初に Next + Prisma + RDS + Auth.js + S3 + Amplify までまとめて決める
- バックエンドを Hono + Cloudflare にする
- 公開ページの最初から SSR する

## 理由

- Next はマジックとパフォーマンスが嫌、という判断
- Vercel を使うことと Next を使うことは別。Vite の静的配信は Lambda の cold start の話ではない
- 閲覧者はログインしない公開ページなので、最初から SSR は要らない
- Go はドメインが Go 必須だからではなく、バックエンド内部の型の穴を小さくするため
- スタックは段階的に決める。最初に必要なのは公開ページの骨組みだけ
