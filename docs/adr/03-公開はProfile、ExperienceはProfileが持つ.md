# 公開は Profile を入口にし、Experience は Profile が持つ

## 決定

Account はログイン主体とする。学校 Google でログインし、自分の Profile を編集するために使う。

Profile は公開される人とする。Username を持ち、Experience の所有者でもある。

公開ページは Account を経由しない。`Username` から Profile を引き、そこにぶら下がる Experiences を読む。

Username は公開 URL 用でユニークとする。使える文字は小文字英字と数字のみ。変更後、旧名が使われていなければ再利用できる。

プロフィール上の担当領域は、Profile 自身が持つ値ではなく、経験から集計する。

Experience は DB の id で識別する。削除したら消える（タイムラインからも無くなる）。編集・削除の admin 権限は、異議対応用に後で考える。MVP には含めない。

凍結は明示状態にしない。学校アカウントでログインできない結果として編集不可になる。

日程は日単位の単日または期間のみとする。月だけ（例: 4月〜6月）は許さない。同日に複数件あるときの並びは、登録順（id 順）でよい。

イベント種類は固定リストとし、該当しない場合用に「その他」を入れる。担当領域も固定リスト＋「その他」とする。役割は自由記述のままとする。

写真は MVP では1経験1枚までとする。無いときは項目自体を出さない（既存の決定どおり）。

認証基盤の実装手段（どのライブラリか等）は未決のままにする。

## 切った案

- Experience の所有者を Account にする
- 公開ページでも Account を辿る
- Username に大文字を許す / URL 上で大文字小文字を区別する
- 担当領域を自由記述にする
- 凍結を明示状態として持つ
- 月だけの日程を許す
- admin による削除を MVP に含める

## 理由

- 公開ページはログインしない。Account に Experience をぶら下げると、公開側でも Account を意識することになりやすい
- Username は URL に使う。大文字小文字の区別は URL では分かりづらいので、小文字と数字にそろえる
- 担当領域を自由記述にすると、経験からの集計で表記ゆれがそのまま並ぶ。イベント種類と同様に固定＋その他にする
- admin は異議申し立てなどで消せるようにしたいが、design doc の MVP には無い
