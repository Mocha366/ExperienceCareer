# 公開プロフィールは、プロフィール上部とタイムラインの並びで固定する

## 決定

公開ページ（採用担当者が URL を開いて見る画面）の並びと項目は、v0 で出したデザインの最終版で固定する。

並び:

- 上にプロフィール
- 下にイベントキャリアのタイムライン（時系列。最終デザインでは新しいものが上）
- 経験の詳細は、この画面では作らない。詳細の issue は、起票を頼まれたときに出す

プロフィールに出すもの:

- 名前
- 自己紹介（空なら出さない）
- 学校・学科（空なら出さない）
- 担当領域タグ: 企画 / 運営 / 広報 / 配信 / MC

タイムライン各件に出すもの:

- イベント名
- 役割（本文。例: 運営リーダー、機材統括、広報担当）
- 実施日程（1日または期間）
- 規模（来場者○人）
- 担当領域タグ（見出しは「領域」）
- イベント種類タグ（見出しは「種類」）
- 写真（ある件だけ。無い件は写真欄を出さない）

場所（会場）は出さない。
空欄は出さない。
ログイン・編集・検索は、この画面の対象外。
最終デザインにある「公開中 / 最終更新」は、必須項目としては決めていない。

見た目の雰囲気はあとからイベントっぽく変えてよい。変えないのは並びと項目である。

## 切った案

- 規模を参加者数にする
- タイムラインに会場・場所を出す
- タグ見出しを `EVENT` / `ROLE`（当初は `ROLELE`）にする
- 公開ページより先に詳細画面や技術スタックを決める

## 理由

- 規模は、来場者の方が見た目として子供っぽくない、という判断
- 場所は design doc の必須項目に無く、デザインからも外すと決めた
- `ROLELE` / `ROLE` は役割本文と担当領域タグが混ざって見える。見出しは「領域」と「種類」にした
- 詳細とスタックは段階的に決める。最初に必要なのは公開ページの骨組みだけ
